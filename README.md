# MiNo

常驻 Windows 桌面的极简「今日待办」浮窗。按一下快捷键唤起,输入,回车 —— 记完了。

它不是又一个 Todo 应用。评价它的标准只有一条:**记一个任务的阻力够不够低**。
所以这里没有账号、没有云同步、没有分类标签、没有 Markdown、没有通知和确认框,
甚至连主窗口都只有 280×380 那么大。


---

## 下载与安装

到 [Releases](https://github.com/jackpunck/MiNo/releases) 页面下载最新版,有两个文件:

| 文件 | 用途 |
|---|---|
| `MiNo_0.3.0_x64-setup.exe` | 安装包。双击安装,之后从开始菜单启动。 |
| `MiNo.exe` | 便携版。**双击就能跑,不写注册表、不需要安装。** |

拿不准就下便携版 —— 它不碰系统,想删掉直接把文件删了就行。

> **从 MiniMemo(0.1.x)升级上来的话**:这个版本改了程序的内部标识符,安装包
> 名字也从 `MiniMemo_*` 变成了 `MiNo_*`,Windows 不认为它们是同一个应用,所以
> **不会自动升级**。请先从「设置 → 应用」里卸载旧版,再装新版。
>
> **你的数据不会丢。** 首次启动时 MiNo 会把 `%APPDATA%\com.minimemo.app\` 整个
> 接管过来(待办、背景图、导入的字体都在里面),老目录原样保留。详见「数据与隐私」。

**系统要求:** Windows 10 1803+ 或 Windows 11,64 位。

## 怎么用

装好后启动,窗口出现在屏幕上,光标已经在输入框里。就这样:

1. **输入** 今天要做的事
2. **回车** 保存
3. 重复

输入框不会失去焦点,可以一条接一条地敲。

**当你手头有别的窗口时**,按 `Alt + Space` 把 MiNo 唤到最前面,敲完再按 `Esc` 让它退下去。

| **真正退出** | **右键任务栏托盘图标 → 退出** |

## 功能说明

### 任务与跨日

每天第一次打开时,MiNo 会自动做一次「跨日结算」:

- **昨天已完成的**任务移入归档,不再占地方(最多保留 500 条)
- **昨天没做完的**保留下来,并标上日期前缀 —— 你一眼能看出它是从哪天拖过来的

底部会显示 `进度: 3/7`,告诉你今天完成了多少。

### 修改任务

打错字了不用删掉重建 —— **双击任务文字**就能就地改。改的是文字本身,顺序、字体、
创建日期全都不动。

| 动作 | 怎么做 |
|---|---|
| 开始改 | 双击任务文字(文字会全选,直接打字即替换) |
| 保存 | 回车,或者点到别处 |
| 放弃 | `Esc`,恢复成原来的文字 |
| 清空 | 视同放弃 —— 任务不会变成空行 |

保存过程中出错的话,你敲的内容会留在编辑框里,不会凭空消失。

### 拖动排序

按住任务上下拖就能调整顺序,松手即生效,重启后保持。

已完成的任务不参与拖动 —— 它们永远沉在列表底部,拖不过去。

> 窗口只有 380px 高,大约显示 8 行。**超出可视范围的任务拖不到**。
> 要调整远处的项,先缩短文本或清掉几条。

### 窗口与边缘吸附

窗口默认漂浮在桌面右上角,可以按住标题栏拖到任意位置,位置会被记住。

**拖到屏幕边缘附近,它会自动吸附上去,并收缩成一条 4px 的感应条**;鼠标碰一下
就展开,移开 0.5 秒后又缩回去。这样它平时几乎不占地方,需要时又伸手可及。

按住标题栏的任意位置(包括「MiNo」那几个字)都能拖动窗口;那 5 个图标按钮
不参与拖动,点它们就是点它们。

多显示器也支持。如果上次的位置对应的显示器已经拔掉了,窗口会回到主屏。

### 什么时候会自己冒出来

**鼠标碰到感应条,它就展开。**

只有一种情况例外:**前台正压着一个全屏程序**(全屏视频、全屏演示、F11 的网页)
时它保持安静 —— 那种场合弹出一块浮窗是真的打扰。桌面、普通窗口、窗口化的
浏览器都算「可以用鼠标够到它」的情况,碰一下就出来。

- **你切到别的程序**(Alt+Tab 等)→ 如果它吸附在边缘,立刻收缩成感应条
- **你切回 MiNo**(按 `Alt + Space`,或从托盘唤起)→ 自动展开
- **鼠标挪到感应条上** → 展开(全屏程序在前台时除外)
- 想叫它出来而它正缩着:**按 `Alt + Space`**,这是任何时候都管用的入口

### 鼠标离开就收起

鼠标移出窗口 0.5 秒后自动收起:

- **已经吸附在边缘** → 缩回感应条
- **停在屏幕中间** → 直接隐藏窗口

和点标题栏那个 `—` 是同一个行为。下面两种情况不会收起:

- **设置面板开着**的时候(否则你点不到)
- **你正在输入框里打字**的时候(停手 2 秒后恢复判断)

### 全局快捷键

默认是 **`Alt + Space`**。

Windows 把这个组合保留给了「打开窗口系统菜单」,所以有时候抢不到。抢不到时
MiNo 会自动退到 **`Ctrl + Alt + Space`**,并且在设置面板里显示**实际生效**的那个。

### 托盘

关闭按钮 `✕` **只隐藏窗口,不退出程序** —— 否则托盘图标和快捷键会一起消失。

真正退出只有一条路:**右键任务栏托盘图标 → 退出**。

### 背景

默认是毛玻璃效果(亚克力),透出一点桌面,但看不清内容。

点 🖼 可以换成自己的图片(支持 **PNG / JPG / WebP**,上限 32 MB)。图片会被
**完整显示,不裁剪也不变形**,剩下的空白由同一张图放大模糊后填满当氛围底色。

图片会被复制进 MiNo 的数据目录,所以**之后移动或删除原图都不影响**。
导入时按文件内容的「魔数」判断格式,不看扩展名。

### 文字可读性

背景图清晰可见的代价是:正文直接压在图上,而图片亮度不可控。有一组工具对付它:

1. **文字颜色**(设置面板里的色块)。亮图配深字、暗图配浅字。
2. **投影方向自动反转**。选浅色字就配深色投影,选深色字就配浅色光晕 ——
   保证任何颜色在任何图上都还有轮廓。
3. **背景遮罩浓度滑块**(默认 28%)。前两样都调不满意时的兜底。

没设自定义图片时文字颜色照样能调,但滑块会换成「背景模糊」(0–20px),
调整的是毛玻璃的强度。两个滑块互斥,只显示当前真正管用的那一个 —— 不留拖了没反应的死控件。

### 字体

设置面板里可以改字体,两个来源:

- **系统字体** —— 列出本机已装的所有字体,每个名字**用它自己的字体渲染**,
  所见即所得。可搜索。
- **导入字体文件** —— 支持 `.ttf` 和 `.otf`,同样会被复制进数据目录,原文件删了也不影响。

**每条任务会记住自己创建时用的字体。** 改字体只影响此后新建的任务,已有的任务
保持原样 —— 换字体不会把你之前的记录一起改掉。

想让已有任务也换成当前字体,点设置面板里的 **「应用到全部任务」**,一次性刷过去。

> 不支持 `.ttc`(TrueType Collection)。一个 `.ttc` 里装着多个字体,浏览器侧
> 无法只取其中一个。与其导入后静默失败,不如当场告诉你换 `.ttf` / `.otf`。

## 检查更新

设置面板最底下有版本号和一个 **「检查更新」** 按钮。点一下会去 GitHub 的公开 API
查一次最新版本,告诉你「已是最新」还是「发现新版本」(后者多一个「前往下载」按钮,
会用系统默认浏览器打开 Release 页面)。

**只有你点它的时候才会联网**,不会开机查、不会后台定时查。检查结果不落盘,
关掉设置面板就没了。

## 数据与隐私

**MiNo 不做任何后台网络活动。** 没有账号,没有遥测,不会自动上报任何东西。

唯一会联网的地方就是上面那个「检查更新」:只有你点它的时候,才会向 GitHub 的公开
API 发一次**只读**请求(`GET /repos/jackpunck/MiNo/releases/latest`),不发送
任何本地数据。

> 想彻底断掉这条通道:把 `src-tauri/tauri.conf.json` 里 CSP 的 `connect-src` 中的
> `https://api.github.com` 删掉,重新构建即可。删掉之后「检查更新」会提示连不上,
> 其余功能完全不受影响。

所有数据都在你自己机器上的一个目录里:

```text
%APPDATA%\com.mino.app\
├── data.json          # 全部状态:任务、设置、归档
├── bg_image.jpg       # 自定义背景图(如果有)
└── fonts\             # 导入的字体
```

> 目录名取自程序的内部标识符 `com.mino.app`,所以是 `com.mino.app\`
> 而不是 `MiNo\`。
>
> **从 MiniMemo 升级上来的用户**:0.2.0 之前那个目录叫 `com.minimemo.app\`。
> 首次启动 MiNo 时会自动把它整个搬过来(待办、背景图、导入的字体、日志一起),
> 日志里会留下一条 `数据目录已接管`。搬迁**不删除老目录** —— 万一哪里没搬对,
> 你的东西还在原地。要是日志里出现的是「接管失败」,按它给的路径手动挪一下即可。

写入采用「临时文件 → 落盘 → 改名」,断电或崩溃都不会留下半截 JSON。
万一 `data.json` 真的损坏了,启动时会把它**自动备份**成
`data.json.<时间戳>.broken`,并用空白数据继续启动 —— **数据文件出问题永远不会
导致程序打不开**。

导入的字体和图片一律按内容哈希重命名,你自己的文件名不会落到磁盘上。

## 已知限制

- **仅支持 Windows。** 窗口透明、边缘吸附、托盘行为都是按 Windows 实现的。
- **全屏程序在前台时,鼠标碰感应条不会展开。** 见上文「什么时候会自己冒出来」——
  这是有意为之:全屏看视频或演示时被浮窗挡住是很烦的事。其余情况碰一下就展开。
- **`Alt + Space` 可能被系统占用。** 见上文「全局快捷键」,会自动回退。
- **`.ttc` 字体集合不支持。**
- **拖动排序不会自动滚动。** 超出可视区的任务拖不到,原因见上文。
- **边缘吸附依赖鼠标命中测试。** 窗口收缩成 4px 感应条后能否稳定被唤起,
  与具体系统环境有关。如果你遇到了「缩起来之后碰不出来」,请提 issue。

## 从源码构建

### 环境要求

这台机器需要装三样东西:

1. **Rust 工具链**(MSVC 目标),MSRV 1.77.2

   ```bash
   winget install --exact --id Rustlang.Rustup
   rustup default stable-msvc
   rustup target add x86_64-pc-windows-msvc
   ```

2. **Microsoft C++ Build Tools**,需要勾选「使用 C++ 的桌面开发」工作负载
   (含 MSVC v143 与 Windows SDK)。缺了它的典型症状是 `linker 'link.exe' not found`。

   ```bash
   winget install --exact --id Microsoft.VisualStudio.2022.BuildTools \
     --override "--wait --passive --norestart --add Microsoft.VisualStudio.Workload.VCTools --includeRecommended"
   ```

3. **WebView2 Runtime** —— Win11 自带,通常无需操作。

装完**重启终端与编辑器**,否则 PATH 不会刷新。

### 命令

```bash
npm install        # 装 @tauri-apps/cli
npm run dev        # 开发运行(等价于 tauri dev)
npm run build      # 出 NSIS 安装包
npm run icons      # 重新生成 src-tauri/icons
```

构建产物在 `src-tauri/target/release/`。安装包走 **NSIS**;不要用 MSI,
它需要额外启用 Windows 的 VBSCRIPT 可选功能,否则会在 `light.exe` 阶段失败。

前端没有构建步骤 —— `build.frontendDist` 直接指向 `ui/`,改完刷新即生效。

### 不装 Rust 就出包(GitHub Actions)

[.github/workflows/build.yml](.github/workflows/build.yml) 已经配好了:

1. 推 `main` 或开 PR 会跑前端静态检查(`node --check` + 两个自测脚本)和
   `cargo check --all-targets` + `cargo test`(不出包,只为快速反馈)。

   > **触发条件有个坑**:`push` 只监听 `main` 和 `v*` tag,**往其他分支推什么都不会跑**。
   > 要在分支上拿反馈,得开一个到 `main` 的 PR。

2. 想拿安装包:Actions 页面手动触发一次,在该次运行的 Artifacts 里下载。
3. 或者推一个 tag(`git tag v0.3.0 && git push origin v0.3.0`),
   会自动建 Release 并挂上安装包和便携版。

> **要分清「CI 绿过」和「验证过了」。** `cargo check` 不链接、不打包,也**从不运行程序**。
> 它挡得住 API 误用和类型错误,但透明窗口、边缘吸附的命中测试、托盘与全局快捷键
> 在真实桌面上是否好用,只有在 Windows 上跑一遍才算数。

### 图标

`src-tauri/icons/` 里的图标由脚本生成,不依赖任何设计资源:

```bash
node tools/gen-icons.mjs
```

`tauri-build` 会把 `icon.ico` 编译进可执行文件的资源段,缺了它 `cargo build` 直接失败。

## 目录结构

```text
src-tauri/src/
├── main.rs        启动顺序、插件注册、窗口事件分发
├── state.rs       数据模型、原子持久化、损坏容错、跨日迁移
├── commands.rs    暴露给前端的 command
├── window.rs      位置恢复、多显示器兜底、置顶、边缘吸附、前台全屏探测
├── tray.rs        系统托盘
├── shortcut.rs    全局快捷键(含冲突回退)
└── fonts.rs       字体枚举、导入、字节读取

ui/
├── index.html
├── boot.js        首屏字体引导(必须阻塞执行,见文件内注释)
├── styles.css
├── app.js         启动与装配
├── state.js       状态与 command 调用封装
├── todos.js       列表渲染与交互
├── dnd.js         拖动排序
├── appearance.js  文字颜色、背景遮罩、背景模糊
├── window.js      窗口行为、快捷键、悬停展开、活跃状态
├── background.js  背景层
├── fonts.js       字体加载与应用
├── version.js     版本号比较(纯函数,便于单测)
├── update.js      检查更新
└── settings.js    设置面板

tools/
├── gen-icons.mjs      生成 src-tauri/icons(零依赖,手写 PNG/ICO)
├── check-commands.mjs 校验前端 invoke() / listen() 与 Rust 侧的注册是否对得上
└── check-version.mjs  版本号比较的自测

.github/workflows/
└── build.yml      cargo check + test;打 tag 或手动触发时出包
```
